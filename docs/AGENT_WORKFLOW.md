# Pricewave 実装作業の完了条件

最終更新: 2026-09-04

この文書は、ChatGPT/エージェントが `Kenu4000/pricewave-girls` の実装・修正を担当するときの作業完了条件を明文化する。

## 基本ルール

ユーザーから実装・修正・不具合対応を依頼され、GitHubへの書き込み権限がある場合、**PRを作成した時点では作業完了としない**。

ユーザーが明示的に「PRまで」「マージしない」「確認だけ」と指定していない限り、次まで行う。

1. 現在の `main` HEAD と関連する過去PR/コミットを確認する。
2. `docs/PROJECT_HANDOFF.md` と関連ドキュメントを読む。
3. ブランチで実装する。
4. 回帰テストを追加・更新する。
5. PRを作成する。
6. GitHub Actionsで `npm ci` / `npm test` / `npm run typecheck` / `npm run build` が成功するまで確認する。
7. CIが失敗した場合は原因を修正し、最新HEADのCIを再確認する。
8. CI成功後、PRを `main` へマージする。
9. マージ後の `main` HEAD とPRの `merged` 状態を確認する。
10. 大きな仕様・運用変更なら引き継ぎドキュメントも更新する。

**PRがopenのまま、CI待ちのまま、または「マージはユーザー側で」として終了しない。**

## 過去実装の参照

「以前は動いていた」「前の拡張では起きなかった」という報告がある場合、現行コードだけを見て局所修正しない。

- 直近の関連コミット履歴を確認する。
- 挙動を変えたPR/コミットを特定する。
- 変更前のファイルを取得して比較する。
- 旧仕様へ単純に戻すのか、現行仕様を維持しながら回帰だけ直すのかを判断する。

未登録商品探索については、2026-08-08のPR #20 / commit `005e318f29b50545c29eb0a22b11b1447943c9c0` で、旧来のビジュアルノベル検索URLから発売日順のアダルトPCソフト全体検索へ探索範囲が拡大している。状態違い商品の混入などを調査するときは、この変更前後を必ず比較対象にする。

## ローカルSQLiteについて

`prisma/dev.db` はGitHub管理外であり、GitHubコネクタから直接編集できない。DBの実データ削除・修復が必要な場合は、再現可能で安全確認付きのスクリプト/コマンドをリポジトリへ用意し、ユーザーPCで実行できる状態まで持っていく。
