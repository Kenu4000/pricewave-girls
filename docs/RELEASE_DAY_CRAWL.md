# 発売日到達時の巡回周期自動昇格

最終更新: 2026-09-04

## 目的

発売前から登録している商品カードが発売日を迎えたら、現在の巡回周期が `3 / 7 / 14 / 無` のいずれであっても自動的に `1日` へ変更し、発売直後の価格・在庫変動を毎日取得できるようにする。

## 実行タイミング

Edge拡張が登録商品一覧を取得する `GET /api/products` の先頭で判定する。

このAPIは巡回対象を拡張へ渡す直前に呼ばれるため、発売日到達で1日に昇格した商品は**その同じ巡回実行から**1日商品として扱われる。`balanced-crawl-scheduler.js` 側の周期計算変更は不要。

## 判定日

日付はJST（日本時間）で判定する。

駿河屋の発売日表記は `YYYY/MM/DD`、`YYYY-MM-DD`、`YYYY年M月D日` などを `YYYY-MM-DD` へ正規化して比較する。

## 対象

次を満たすカードを発売日到達時に1日へ昇格する。

- 発売日を解析できる。
- 発売日が2026-09-04以降。
- 発売日前、または発売日当日にすでに登録されていた。
- その発売日について自動昇格処理をまだ行っていない。

発売日にPCが起動していなかった場合も、次回 `GET /api/products` 実行時に発売済みであることを検出して1日へ昇格する。

## 対象外

- 機能導入前（2026-09-04より前）に発売済みの商品は既存の巡回周期を変更しない。
- 発売後に新規登録した過去作品は、発売日を理由に1日へ強制変更しない。
- 発売日が不明・解析不能な商品は変更しない。

これにより、既存の旧作カードが導入時に一斉に1日へ戻ることを防ぐ。

## 一度だけ昇格する理由

`Product.releaseCrawlPromotedForDate` に処理済みの正規化発売日を保存する。

同じ発売日で一度処理した後は、ユーザーが手動で7日・14日・無などへ変更しても自動処理が再び1日へ戻すことはない。

発売日が延期・訂正され、正規化後の日付自体が変わった場合は、新しい発売日について再度判定する。

## `crawlIntervalReviewedAt`

発売日到達によって非1日設定から1日へ自動昇格した場合は `crawlIntervalReviewedAt` を `null` に戻す。

そのため `/crawl-review` の「1日設定・未確認」対象として再び確認できる。

すでに1日設定だった商品は巡回周期を変更せず、発売日処理済みマーカーだけを保存するため、既存の確認済み状態は壊さない。

## 新規追加とメーカー周期継承

`lib/product-import-queue.ts` には、新商品のブランドが既存商品と完全に7日・14日・無で統一されている場合、その周期を新商品へ継承する処理がある。

発売日当日に新規追加された商品については、このブランド周期継承を行わない。Productの既定値である1日を優先する。

## SQLite上限

発売日到達商品の更新はProduct IDを400件ずつに分割し、SQLite/Prismaのバインド変数上限を避ける。
