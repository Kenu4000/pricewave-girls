# シリーズ価格推移グラフ

最終更新: 2026-09-04  
実装: PR #90 / merge commit `7ac8ce17bd8cff54fbc50e57acaada1d7764130c`

## 目的

商品詳細ページの既存「価格推移」グラフの下に `シリーズ` ボタンを表示し、押すと、その商品が属するシリーズの登録済み各作品の販売価格推移を1枚のグラフへ重ねて表示する。

今回の実装範囲はこの機能だけ。シリーズ平均・中央値・合計価格、シリーズ編集UI、DBのSeriesモデル、Viewer側表示は追加していない。

## シリーズ定義

2026-09-04に作成した成人向けゲームシリーズ調査表を元に、173シリーズ・1,135タイトルを静的カタログ化した。

ファイル:

- `data/series-catalog-01.json`
- `data/series-catalog-02.json`
- `data/series-catalog-03.json`
- `data/series-catalog-04.json`
- `data/series-catalog-05.json`
- `data/series-catalog-06.json`

DBへシリーズ情報は保存しない。シリーズの正規定義は現時点ではこの静的カタログ。

## 商品タイトルのシリーズ判定

`lib/series-catalog.ts` が担当する。

基本方針:

1. 商品タイトルの状態表記を `splitProductTitleCondition()` で除去する。
2. NFKC正規化・小文字化を行う。
3. 空白とUnicode句読点を除去する。
4. `+`、`×`、`†` などタイトル識別に使う記号は残す。
5. カタログ側タイトルを長い順に照合する。
6. 正規化後の完全一致または前方一致だけを採用する。

部分包含一致は使わない。別シリーズへの誤分類を避けるため。

長いタイトルを優先することで、たとえば `ToHeart2 ダンジョントラベラーズ` を `ToHeart2` 系ではなくダンジョントラベラーズとして判定する。

## 同一作品の複数登録

同じカタログ作品に複数の駿河屋商品が対応する場合:

- 通常品が存在すれば通常品を優先する。
- ランクB/状態違い商品は通常品がある場合はシリーズ線から除外する。
- 通常品が存在しない場合は状態違い商品も利用可能とする。

## 商品詳細ページ

`app/products/[id]/page.tsx` で現在の商品からシリーズを判定する。

シリーズが見つかった場合のみ:

1. 登録商品のID・タイトル・状態を取得する。
2. `buildSeriesProductGroups()` でシリーズ内の作品へ分類する。
3. そのシリーズに必要な `PriceHistory` のみ取得する。
4. `SeriesPriceChart` へ渡す。

既存の `PriceChart` は変更しない。その直下にシリーズUIを追加する。

## SeriesPriceChart

`components/SeriesPriceChart.tsx`

初期状態では `シリーズ` ボタンだけを表示する。

押下後:

- シリーズ名
- 価格履歴が存在する作品数 / カタログ定義作品数
- 同シリーズ各作品の販売価格推移
- 各作品の最新販売価格を含む凡例

を表示する。

各作品を1本の折れ線として同じ時間軸・価格軸へ重ねる。
